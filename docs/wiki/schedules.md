# Расписания

Расписание позволяет WideResearcher автоматически запускать исследование через заданный интервал — без вашего участия.

## Как настроить расписание

1. Откройте детальную страницу любого **завершённого** исследования
2. Нажмите **«Расписание»**
3. Выберите тип повтора, интервал и дату/время первого запуска
4. Нажмите **«Сохранить»**

В списке исследований появится пометка с датой следующего запуска.

## Типы повтора

| Тип | Описание | Когда использовать |
|-----|----------|-------------------|
| **С нуля** (`start`) | Каждый раз создаёт новое независимое исследование | Мониторинг темы: каждый раз свежий срез |
| **Продолжить** (`current`) | Каждый новый запуск добавляет итерацию к исходному исследованию | Углубление существующей цепочки |
| **Углубить** (`deep`) | Каждый новый запуск продолжает предыдущий автоматический запуск | Длинная цепочка с накоплением контекста |

## Интервалы

Доступные единицы: минуты, часы, дни, недели, месяцы, годы. Числовое значение задаётся вручную.

Примеры:
- «Каждые 7 дней» — еженедельный мониторинг темы
- «Каждый 1 месяц» — ежемесячный дайджест
- «Каждые 24 часа» — ежедневное обновление

## Как работает планировщик

Планировщик (`app/scheduler.py`) работает как отдельный процесс в Docker. Каждые 60 секунд он проверяет базу данных и запускает все расписания, у которых `scheduled_at <= сейчас`.

После запуска:
1. Создаётся дочернее исследование с настройками из расписания
2. Задача отправляется в Celery-очередь
3. Текущая запись расписания помечается `COMPLETED`
4. Автоматически создаётся новая запись `PLANNED` со следующей датой

## Как изменить расписание

Откройте **«Расписание»** на странице исследования — текущие настройки будут предзаполнены. Измените нужные параметры и сохраните. Незапущенные (`PLANNED`) записи будут заменены новыми.

## Как отменить расписание

На странице исследования нажмите **«Расписание»** → **«Удалить расписание»**. Текущие запланированные (но ещё не запущенные) записи удалятся. Уже запущенные исследования остаются.

> Расписание работает только если запущен контейнер `scheduler`. Если вы остановили его — запуски не произойдут, но при следующем старте планировщик не запустит пропущенные итерации ретроактивно.
